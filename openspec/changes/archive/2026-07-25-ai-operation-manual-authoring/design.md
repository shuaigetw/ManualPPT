## Context

本變更建立一套以實際瀏覽器證據為基礎的操作手冊製作系統。使用者可從既有腳本、AI 探索或人工示範開始，於同一工作階段中自由切換，再將核准的操作流程執行、驗證並輸出 PowerPoint。

系統涉及瀏覽器控制、桌面錄影、文件解析、AI 推論、敏感資料、長時間任務、高風險 UI 動作與多版本發布。ManualPPT 必須將瀏覽器擷取、流程模型、受治理執行、證據管理與簡報發布分成清楚邊界；所有有副作用的動作都要先經權限、範圍、風險與使用者核准，長時間任務則使用可持久化的檢查點。

第一版只支援 Chrome／Edge，且只能對白名單 localhost 或 staging 使用測試帳號及合成資料。產品由瀏覽器擴充功能與本機桌面程式組成，避免把原始錄影、互動事件與敏感畫面送往未核准的第三方。

## Goals / Non-Goals

**Goals:**

- 從訪談、規格文件與實際 UI 建立可驗證的功能清單和分支流程模型。
- 支援腳本執行與人工示範的雙向切換，並以差異版本安全合併。
- 對使用者選定的範圍提供明確覆蓋結果；選擇全部時執行所有可到達且獲授權的分支。
- 以事件、狀態、截圖與規格來源形成可追溯證據。
- 產生適合不同熟練度、層級、用途、語言與權限的公司品牌 PowerPoint。
- 支援暫停、續跑、終止、分支重試、改版差異與資料保留政策。

**Non-Goals:**

- 不操作正式環境或任意第三方網站。
- 不破解 CAPTCHA、反機器人機制或 MFA。
- 不保存密碼、驗證碼、Token 或真實員工個資。
- 不以機率性的 Agent 探索結果取代 Playwright 回歸閘門。
- 不承諾測試未被使用者選入或無法到達的功能。
- 不在第一版支援 Chrome／Edge 以外的瀏覽器。

## Decisions

### 1. 本機擷取平面與受治理的服務平面

瀏覽器擴充功能擷取 DOM 語意、可存取性角色、穩定識別資訊、滑鼠／鍵盤互動、頁面狀態與截圖；桌面程式負責工作階段、錄影、遮罩、人工接管及本機檔案。後端服務保存正規化流程、版本、執行、證據索引、核准、稽核與發布資料。

相較純雲端瀏覽器，本機平面可降低 PII 與 session 外流風險，亦較容易支援人工登入、MFA、錄影與公司內網頁面。

### 2. 單一正規化流程模型

AI 探索、既有腳本與人工錄製都轉換為同一流程圖。核心概念包含 Project、ApplicationScope、AudienceProfile、RoleSession、WorkflowVersion、State、Step、Transition、Branch、RiskClassification、ExecutionRun、Checkpoint、Evidence、Approval、SourceReference、ManualDraft 與Publication。

Step 保存語意目標而非單一 CSS selector：元件角色、名稱、文字、test id、候選定位器、位置特徵與參考截圖。若新版 UI 無唯一匹配，執行器暫停並要求確認，禁止猜測。

### 3. 差異優先的混合編輯

腳本可隨時暫停並切換人工操作；人工操作產生新增、取代、略過或分支的修正候選。只有經使用者確認才形成新 WorkflowVersion，舊版本保持可還原。一次性繞過不得自動成為標準流程。

### 4. 先盤點、再核准、後執行

AI 先以唯讀方式訪談與盤點網站、模組、角色、任務、元素狀態及可到達路徑，產生功能清單與流程圖。使用者核准本次範圍後才可執行寫入操作。

「全部」指核准範圍內所有可到達功能、角色、單一選項與獨立按鈕路徑。多選欄位預設覆蓋每個選項至少一次，並依風險與選項交互作用增加組合；不展開無限或無實益的笛卡兒積。

### 5. 治理包覆每一個有副作用的動作

所有操作均經 action classification。新增、修改、送出、刪除、付款、核准等動作在執行前通過原使用者權限、工作範圍與 skill 授權交集檢查。高風險動作逐次顯示動作、測試資料、後果、復原方式與一次性授權範圍，取得二次確認後才執行，並寫入 append-only 稽核。

登入與 MFA 進入人工接管或公司核准的憑證流程；敏感輸入不進入事件、影片、截圖與簡報。

### 6. 事件與狀態驅動的證據

系統記錄單擊、雙擊、右鍵、懸停、拖曳、排序、滑桿、框選、多選、捲動、展開、收合、拖放、圖表／畫布等有語意互動，不保存無意義的完整游標軌跡。

截圖在動作完成、欄位狀態確定、頁面／彈窗切換、驗證訊息出現及前後狀態實質改變時擷取。截圖以游標、箭頭或框線標示目標。影片作為輔助證據，不是步驟判定的唯一來源。

### 7. 來源受限的 AI 說明

操作目的、適用情境、環境因素、工序因素、原因與注意事項只能來自已匯入規格、使用者說明與執行證據。缺少來源時標記待確認；文件衝突時列出版本與衝突，禁止自行選擇或杜撰。

### 8. 可恢復的長時間執行

每個安全邊界與分支建立 Checkpoint。失敗時顯示原因、完成範圍與未完成項目，讓使用者選擇暫停並續跑，或終止本次執行。終止時預設保留既有證據並產生未完成草稿；只有明確刪除才移除。持久化技術由實作階段依 ManualPPT 技術棧選定，不綁定特定 Agent framework 或資料庫。

### 9. 先形成手冊腳本，再發布

所有證據先轉成可編輯的 ManualDraft，按主流程、分支流程、例外處理與測試附錄編排。每步包含操作、目標、原因、預期結果、注意事項、截圖與來源。使用者核准後才生成正式 PowerPoint。

發布維度為熟練度、組織層級、用途、語言及角色權限的組合。使用者勾選需要的組合或使用公司範本；系統不得因翻譯或摘要改變已驗證事實。

### 10. 差異維護與保留政策

軟體改版後重跑既有腳本，比對步驟、元素、畫面與結果，只更新受影響的流程與投影片。原始影片採可設定的短期保留；流程、截圖與稽核證據依公司政策保存。測試資料依預先產生且經確認的清理計畫處理。

## Risks / Trade-offs

- [UI 改版造成誤點] → 多特徵語意定位；不唯一時必須人工確認。
- [分支組合爆炸] → 每選項一次加風險導向組合，並明確報告未覆蓋組合。
- [錄影含敏感資訊] → 擷取源頭遮罩、敏感區域規則、發布前掃描與人工閘門。
- [AI 杜撰操作理由] → 每段說明綁定 SourceReference；無來源即待確認。
- [高風險操作誤執行] → staging、假資料、治理檢查、逐次二次確認、kill switch 與 append-only 稽核。
- [長任務中斷] → 持久化檢查點、冪等執行鍵與分支重試。
- [多版本手冊維護成本] → 共用單一事實模型，按需產生版本，不預設產生所有組合。
- [本機與後端狀態不一致] → 事件序號、內容雜湊、斷線佇列與伺服器確認游標。

## Migration Plan

1. 以 feature flag 建立只讀探索與流程模型。
2. 加入人工錄製、遮罩與證據檢視，不啟用自動寫入。
3. 加入受治理的 staging 自動執行、高風險確認及檢查點。
4. 加入手冊腳本審閱、PowerPoint 生成與公司範本。
5. 加入多受眾、多語與改版差異更新。
6. 每階段可停用 feature flag；流程版本與證據採向後相容資料遷移，不刪除稽核紀錄。

## Open Questions

- 第一批公司 PowerPoint 範本與支援語言將由產品導入時配置。
- 原始影片、截圖與手冊各自的預設保存天數需由公司資料治理政策決定。
- Chrome／Edge 擴充功能採企業集中部署或使用者安裝，需在實作前由 IT 決定。
